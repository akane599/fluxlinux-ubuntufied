# Architecture
*Last Updated: 2026-11-02*

Paths below abbreviate `app/src/main/kotlin/com/ivarna/fluxlinux/` as `KT/`.

## Layers
```
MainActivity (manual Screen enum; opens on the terminal)      ui/screens, ui/onboarding, ui/components, ui/theme
        │  collectAsState on singleton StateFlows
        ▼
core/* singleton `object`s (no ViewModels, no DI)
  install/   onboarding runner, `InstallController` (process-scoped install owner + busy guard), rootfs download + SHA pins, per-distro profiles
  terminal/  host prefix extraction, command builders, session registry, shell runner, PulseHost
  desktop/   GUI session start/stop/readiness            service/  foreground services, `LaunchTargets`
  root/ chroot/ proot/   su, BusyBox, per-container state  gpu/  VirGL/Panvk drivers
  utils/     SharedPreferences wrappers, `UbuntuRuntime` (active Ubuntu install SSOT), EmbeddedX11 (X11 prefs launcher)
  files/     SAF DocumentsProvider + `GuestFs` seam (local or su) for the Ubuntu rootfs    system/  SafeFiles, ~/storage links, storage perms
        │  ProcessBuilder via ShellCommandRunner / RootShell
        ▼
Host prefix  filesDir/usr  (from bootstrap.tar + jniLibs libbash/libproot/libloader)
        │  proot / chroot
        ▼
Guest rootfs (Ubuntu-first: `ubuntu` PRoot or `ubuntu_chroot`; 12 distros supported, downloaded from GitHub release tag `rootfs`)
        ▲ X11 via in-process Termux-X11 server (:termux-x11)   ▲ audio via host PulseAudio
```

## Key flows
**First run (onboarding → host → rootfs)**
1. `KT/ui/onboarding/OnboardingFlowScreen.kt` calls `TerminalLauncher.prepareHost`.
2. `KT/core/terminal/BootstrapInstaller.kt` `ensureExtracted` untars the asset `bootstrap.tar` with a hand-rolled tar reader. It preserves existing proot containers by moving `usr/var/lib/proot-distro` aside to `.preserved_proot_distro`. `recoverStrandedAside` restores an aside left by an interrupted run. An existing aside is never deleted; it is renamed with a timestamp instead.
3. `HostScriptDeployer.deployScripts` runs, then `setup_termux.sh`. `deployScripts` also calls `HostShLink.ensure`, which adds `usr/bin/sh -> bash` to installs extracted before the bootstrap had it (`BootstrapInstaller` doesn't re-extract on upgrade). It never replaces an existing `sh`.
   - Ubuntu 26.04's rust-coreutils ships hard links that proot `--link2symlink` turns into `.l2s` symlinks, and Ubuntu's argv[0] check then refuses every utility. `setup_ubuntu_family.sh` therefore installs `coreutils-from-gnu` right after `apt-get update`. `KT/core/terminal/GuestCoreutilsRepair.kt` self-heals installs that are already broken: before proot sessions (`GuestSessionFactory`), the desktop start (`DesktopLauncher`) and `InstallSessionFactory.openProotInstall`, it repoints `usr/{bin,sbin}/<u>` from l2s-broken `lib/cargo/bin/coreutils/<u>` to `gnu<u>`.
4. `KT/core/install/OnboardingInstallRunner.kt` drives `runProot`/`runChroot` phases from `BaseDesktopInstallPlan`. Onboarding's Options step offers PRoot vs chroot only when an off-main root probe succeeds (`RuntimeChoiceSection`; `onboardingInstallRuntime` falls back to PRoot only on a definite "no root" and keeps the retry's runtime). The chroot path runs `setup_guest_chroot.sh` via `KT/core/install/ChrootSetupCommand.kt` (root-only staging, SHA re-verified, exit 127 otherwise; also used for terminal installs). It is owned process-wide by `KT/core/install/InstallController.kt` (state as `StateFlow`, so rotation or leaving the screen never cancels an install; one install at a time across onboarding and the install wizard). The controller refuses to start while an uninstall session is open (`UninstallSessionFactory.isAnyUninstallRunning`), and `hostRepairAllowed` blocks host repair mid-install. Component re-runs from Distro Settings assemble their script with `KT/core/install/GuestComponentPayload.kt` (env exports, then `flux_guest_common.sh`/`flux_gpu_common.sh`, then the script).
5. `RootfsDownloader.ensurePresent` downloads the rootfs and checks SHA-256 and free space against `DistroInstallProfile`/`PinnedReleaseArchive` pins.
6. Guest scripts run, then `StateManager.setOnboardingComplete`/`setDistroInstalled`.

**Ubuntu runtime and guest user (feat/ubuntu-chroot)**
1. `KT/core/utils/UbuntuRuntime.kt` is the SSOT for which Ubuntu the Ubuntu-first surfaces act on: `UbuntuRuntimeMode` PROOT (`ubuntu`) / CHROOT (`ubuntu_chroot`), pref `flux_ubuntu_runtime`, `modeFlow` (observable), `activeDistroId`, `isUbuntuId`/`isChrootId`. Home, onboarding, the terminal and Settings all use the active id (the old `UBUNTU_DISTRO_ID` is gone). Both installs coexist; switching only changes the pref.
2. `UbuntuInstallProbe` (pure `check` + off-main `probe`: CHECKING / INSTALLED / NOT_INSTALLED / NO_ROOT; `chrootEverInstalled` avoids a `su` prompt for PRoot-only users) and `UbuntuRuntimeSwitch` (pure `decide`: UNCHANGED / SWITCH / STOP_DESKTOP_FIRST / NO_ROOT; `apply` sets the mode and calls `UbuntuFiles.notifyRootsChanged`). Desktop auto-start (and `UbuntuLaunchPreferences`) was removed on `feat/terminal-first`: the app opens on the terminal.
3. UI: Settings `KT/ui/components/UbuntuRuntimeCard.kt` (segmented PRoot/chroot, root status); Home hero runtime chip plus `UbuntuStatus.CHECKING`/`NEEDS_ROOT`. `HomeScreen` re-probes root only per `homeRootProbeAllowed(reason, lastRoot)` (INITIAL once, RESUME/REFRESH only after a grant, RETRY on demand) so a denied `su` prompt never loops. `TerminalScreen` calls `ChrootDetection.warmUp` off-main so later main-thread checks hit the cache.
4. Guest user: `UbuntuRuntime.guestUserFor` gives `akane` for both Ubuntu installs and `flux` for every other distro. `KT/core/root/GuestUsers.kt` adds name validation, `userFor`, `prootLoginUser` (falls back to `flux` while passwd lacks `akane`), `prootHome` and `scriptEnv` (exports `FLUX_GUEST_USER`; guest scripts default to `flux` without it).
5. `KT/core/terminal/GuestUserMigration.kt` renames an existing PRoot `flux` guest to `akane` in place (home rename plus compat link `home/flux -> akane`, per-user spool/sudoers/doas, account files with `passwd` last as the commit point; resumable, `CONFLICT` when both exist, one process-wide lock). `migrateIfNeeded` runs from `GuestSessionFactory`, `InstallSessionFactory`, `OnboardingInstallRunner`, `DesktopLauncher` and `MainActivity`. Chroot installs are migrated by root inside the chroot (`fluxlinux_chroot.sh` user-migration block, an identical copy in `setup_guest_chroot.sh`, enforced by `ChrootGuestUserScriptTest`).

**Desktop session**
1. `KT/core/desktop/DesktopLauncher.kt` `start` probes install state (`TerminalLauncher.isProotInstalled`/`isChrootInstalled`).
2. It runs `start_gui.sh` or `start_gui_chroot.sh` through `ShellCommandRunner.runStreamedCancelable` (its own process group, so cancel kills proot/apt/git children too) and starts `DesktopSessionService`. Start/stop ordering is `KT/core/desktop/DesktopRunState.kt` (pure, unit-tested): every start/stop opens a generation, callbacks from older generations are ignored, and a start waits for a running stop script instead of cancelling it.
3. PulseAudio comes from `app/src/main/assets/scripts/host/start_pulse_host.sh`, wrapped by `PulseHost`. It listens on a unix socket `$PREFIX/tmp/pulse-native` only (no TCP). Guests reach it at `unix:/tmp/pulse-native` (proot, `--shared-tmp`) or `unix:/mnt/host-tmp/pulse-native` (chroot).
4. The X server is launched by the `start_gui*.sh` scripts: `app_process` with `loader.apk` runs `com.termux.x11.Loader :0` (CmdEntryPoint), then the script waits for `$TMPDIR/.X11-unix/X0`. `DesktopLauncher.openX11` opens `com.termux.x11.MainActivity`; it is the only opener (the scripts' early `am start` was removed in SQ-23 so the display can't open before `FLUX_DESKTOP_READY`).
5. Readiness: the Running phase only flips on the guest marker line `FLUX_DESKTOP_READY` (`DesktopLauncher.isDesktopReadyLine`), which the proot `start_gui.sh` and chroot launchers print only if the desktop process is still alive about 2 s after launch. The host X-socket line is never a marker; `DesktopSessionQuery` serves state queries.
6. `LinuxCommandBuilder.currentMethod` ("proot" or "chroot") selects `ProotCommandBuilder` or `ChrootCommandBuilder`. Chroot sessions first reopen their pty by path as fds 0-2 (`ChrootCommandBuilder.REATTACH_TERMINAL`, root side): KernelSU's `su` hands root an fd wrapper whose reads ignore O_NONBLOCK, which froze full-screen programs (codex) until a key press. The wrapper still reports the `/dev/pts/N` path, so `ls -l /proc/$$/fd/0` can't tell them apart; `stat -L -c %t:%T /proc/$$/fd/0` shows `88:N` on the real pty and `0:0` on the wrapper.

**Embedded terminal**
1. `KT/ui/screens/TerminalScreen.kt` hosts `com.termux.view.TerminalView` (jitpack terminal-view). There is no distro picker (v2.1.2): with no sessions it auto-opens the active Ubuntu install's default user shell (PRoot or chroot, per `UbuntuRuntime.mode`; `TerminalSessionChoices.defaultUser`) once per entry (failure shows a retry state). There is no top bar or tab row (v2.1.6): a Termux-style left drawer (`TerminalDrawerSheet`) lists sessions (tap to switch, 48dp ✕, long-press Close / Close other tabs) and holds "New Ubuntu session" (long-press or ▾ offers Ubuntu root, Ubuntu chroot when root is granted + installed, and the Termux host shell), the extra-keys switch, then Ubuntu page / Files / Settings rows (the terminal is the app's home; Back from those returns here). `KT/ui/terminal/TerminalSessionDefaults.kt` picks those cards from `TerminalShellCatalog`. The drawer opens from the ☰ key at the left of the extra-keys bar or by a swipe towards it anywhere on the terminal. `keepTerminalGestures` (`KT/ui/terminal/TerminalGestures.kt`, Initial pass on the AndroidView) leaves those swipes to the drawer's drag and claims every other gesture for the `TerminalView` (scrolls with sideways drift, pinch, selection) via `requestDisallowInterceptTouchEvent`. `DrawerEdgeZone`, a 20dp×192dp left-edge strip with `systemGestureExclusion`, keeps edge swipes from becoming Back.
2. `FluxTerminalSessionManager.openSessionAfterHost` calls `GuestSessionFactory.prepareSession`, which creates `com.termux.terminal.TerminalSession` (`:terminal-emulator`).
3. `SessionRegistry` keeps sessions alive through `AppTerminalService`. Its notification and the drawer carry "Hold wakelock" (`KT/core/terminal/TerminalWakeLock.kt`: one PARTIAL_WAKE_LOCK, opt-in, no timeout like Termux); the service releases it with the last session and in `onDestroy`.
4. Variants: host shell (`HostCommandBuilder`), install, uninstall, component and root-script sessions. `UninstallSessionFactory` tracks open uninstalls so installs and desktop starts refuse a rootfs being removed.
5. Extra-keys bar: `KT/ui/terminal/TerminalExtraKeys.kt`. Two fixed utility columns mirror each other outside the scroll: ☰ (opens the drawer) at the left and Paste at the right (long-press: the clipboard menu). Between them, two rows of 12 keys that share one horizontal scroll: each starts with Termux's default 7 (`ESC / ― HOME ↑ END PGUP` / `↹ CTRL ALT ← ↓ → PGDN`) and continues past the right edge with `| ~ _ \ BKSP` / `SHFT Fn INS DEL ENT` (row data test-pinned by `TerminalExtraKeysLayoutTest`). All 12 columns show unscrolled when cells would be ≥56dp; word labels step down to labelSmall below 44dp cells (`COMPACT_LABEL_CELL_WIDTH`); Fn adds F1–F12 as a third row on the same grid. Held arrows, PGUP/PGDN, BKSP and DEL repeat on the `KT/ui/terminal/KeyRepeat.kt` schedule: Termux-constant by default (first repeat at 400 ms, then every 80 ms), or accelerating (100→30 ms) when `TerminalPreferences.isKeyRepeatAccelerated` (the "Accelerate held keys" switch in Terminal settings) is on.
6. Clipboard and links: `KT/ui/terminal/TerminalClipboard.kt`. Paste always goes through `TerminalSession.onPasteTextFromClipboard` (→ `SessionRegistry` → `emulator.paste`: bracketed paste, ESC/C1 stripped); Ctrl+Shift+V and KEYCODE_PASTE paste too. A single tap on a link (`getColumnAndRow` + `getWordAtLocation`, which spans wrapped rows; `KT/ui/terminal/TerminalLinks.kt` accepts http/https/www only) opens it with ACTION_VIEW + CATEGORY_BROWSABLE, otherwise the tap shows the IME as before. This holds in every mode, also in mouse-tracking apps (Claude Code / Codex full screen, tmux mouse on): TerminalView sends them the click first and still calls the client, so a link opens there too (the user's choice; only vim with mouse=a also moves its cursor). The selection toolbar's "More…" opens a context menu: Paste, Open a link… (`TerminalLinksDialog`; each link once, in reverse order of its first appearance (`TerminalLinks.findAll` is `distinct()`), so a link printed again later keeps its earlier place), Copy all output, Share output (last 100k chars). "Copied" toasts only below Android 13.
7. Ubuntu zsh profile: `KT/core/terminal/ZshPluginSet.kt` is the single source of truth for the oh-my-zsh plugin order, the managed `.zshrc` block (plugins built at start-up from what is installed; Up/Down bound to history-substring-search), apt deps (fzf, zoxide, command-not-found) and the fzf-tab clone. `GuestZshrcRepair` upgrades existing Ubuntu profiles that still carry the Flux default plugin line, and swaps an unedited earlier list in the managed block for the current one (`PREVIOUS_PLUGIN_LISTS`; one-shot key `guest_zsh_plugins_v2_<id>`; backup `.zshrc.flux-bak`), `core/install/ProotZshBootstrap` clones fzf-tab and installs the deps lazily (as its own process group with a timeout), and `scripts/common/setup/setup_customization_xfce.sh` and `scripts/chroot/fluxlinux_chroot.sh` carry verbatim copies enforced by `ZshPluginSetTest`.

**Root / chroot**
1. `KT/core/root/RootShell.kt` resolves `su` once (single-flight walk over `SU_TRIALS`; a probe timeout stops the walk, nothing cached on failure). `captureResult`/`executeSync` take `timeoutMs` (exit -2 = timeout, -1 = no su; see `failureReason`). Root commands are wrapped with a pid marker so cancel or timeout tree-kills the root job (`killTreeThenDestroy`, `buildTreeKillScript`), off the caller thread.
2. Root-run files live in a root-only stage dir `ChrootPaths.ROOT_STAGE_DIR` = `/data/adb/fluxlinux/<applicationId>/` (M14), never the shell-writable `/data/local/tmp` (legacy copies are only removed). `fluxlinux_chroot.sh` and its `resolve_bb.sh` sidecar are staged there and SHA-256-verified against the APK assets (`RootShell.ensureChrootHelper`/`stageVerified`). `BusyBoxPaths.CANDIDATES` lists the BusyBox locations; BusyBox is used in place, never copied.
3. `app/src/main/assets/scripts/chroot/fluxlinux_chroot.sh` (v3.0) takes a shared mkdir mount lock (`<chroot>/.flux_mount.lock`, owner file `pid boot_id epoch`). A lock is broken when its holder is gone, pid-less, from a previous boot or not a FluxLinux script, under a second mkdir mutex. `stop_*_gui.sh` and `uninstall_*_chroot.sh` carry an identical copy (keep them in sync; `MountLockTest`). Each chroot session registers `<chroot>/.flux_sessions/<pid>`, so mounts stay while any session lives. Install state markers: `.flux_configured` (setup finished), `.flux_extract_ok` (rootfs extracted, holds the SHA; also used for proot containers), `.flux_uninstalling` (set by the uninstall scripts; `fluxlinux_chroot.sh` refuses to mount while it exists).
4. v3.0 adds: validated `--user USER|root` (default `akane` when the guest passwd has it, else `flux`; `ChrootCommandBuilder` resolves via `GuestUsers.resolveChrootUser`), `links`/`links-status` modes (the `~/storage` links, see File access), the flux-to-akane migration block, and a zsh profile seeded from `ZshPluginSet` (test-enforced copy). `setup_guest_chroot.sh` adds the `aid_inet` (3003) and `aid_net_raw` (3004) groups so guest users can open sockets, and gives new users a password equal to the user name. `KT/core/terminal/ChrootZshrcUpgrade.kt` upgrades a chroot `.zshrc` through the helper's `b64` mode (root I/O inside the chroot, so a guest symlink cannot redirect the write).

**File access (v2.1.0)**
1. `KT/core/system/GuestStorageLinks.kt` `ensure(ctx, distroId)` creates Termux-style `~/storage/{shared,downloads,documents,dcim,pictures,music,movies}` links in the guest homes (`/home/akane`, a still-real legacy `/home/flux`, and `/root`). PRoot links point at `/storage/emulated/0[/...]` and are made directly by the app; chroot distros delegate to `fluxlinux_chroot.sh links`/`links-status` through su (`CHROOT_LINKS` target `/sdcard`, the only bind; background threads only, null when unknown). It is idempotent and never deletes or replaces anything. It is called from Home, `GuestSessionFactory`, `DesktopLauncher` and `OnboardingInstallRunner`.
2. `KT/core/system/SharedStorageAccess.kt` handles permission state and requests: All files access on ivarna API 30+, legacy READ/WRITE below 30.
3. `UbuntuDocumentsProvider` serves the active mode's rootfs to SAF. `KT/core/files/GuestTree.kt` (`GuestLayout` PROOT/CHROOT) resolves guest-style symlinks confined to the rootfs, the container and shared storage on top of the `GuestFs` seam (`GuestFs.kt`): `LocalGuestFs` (java.nio, PRoot rootfs), `RootGuestFs` (chroot rootfs through su: `RootScripts` shell scripts, BusyBox first, run by `RootRunner` with a 10 s default and 30 min long budget for copy/delete/move, a failed copy's partial output is removed) and `SharedStorageRoutingFs` (chroot: `/sdcard` links go straight to shared storage; cross-backend move/copy refused). `GuestDocumentPaths.kt` keeps the pure doc-id parsing and constants. Document ids are namespaced per mode, so a grant from one mode never resolves in the other. Docs reached through a symlinked directory are browse/create only: no delete, move or rename, and no tree-grant child. Chroot only: host mounts inside the rootfs (`/proc`, `/sys`, `/dev`, the `/sdcard` bind) are list-only.

**Settings**: SharedPreferences only. See [patterns.md](patterns.md).

## Boundaries and invariants
- Every host path derives from `BuildConfig.APPLICATION_ID` (`TermuxHostPaths`). The bootstrap debs bake in `/data/data/<appId>/files/usr`, so a bootstrap is valid only for its own flavor. See [native-bootstrap.md](native-bootstrap.md).
- Host binaries are exec'd from `nativeLibraryDir` because of W^X, so `jniLibs.useLegacyPackaging = true` must stay.
- `FluxApp.onCreate` refreshes the host env because `nativeLibraryDir` changes on every app update.
- Legacy v1.x Termux-based distros are bridged by `KT/core/legacy/`, and `Screen.SETTINGS_LEGACY_TERMUX` exposes them.
- **Child processes run as their own process group** so cancel/timeout reaches descendants: `ProcessGroupLauncher.wrap` (a `set -m` bash wrapper from `libbash`, no `setsid` needed) in `ShellCommandRunner.kt`, with a SIGKILL escalation on destroy. Do not start long host jobs with a bare `ProcessBuilder`.
- `LaunchTargets` (`KT/core/service/LaunchTargets.kt`, pure) validates what a notification/termux-x11 intent may open (`EXTRA_TARGET_PAGE`: home, terminal, install) and which distro ids a `fluxlinux://callback?name=distro_(un)install_<id>` callback may name (callbacks are unauthenticated).
- The activity-to-X-server socket uses full-length framed I/O: `termux-x11/src/main/cpp/lorie/conn_io.h` (`lorie_read_full`/write loops, payload caps) included by `activity.cpp`, `cmdentrypoint.cpp`, `buffer.c`, `renderer.cpp`.
- XFCE theme/icon/cursor archives: `KT/core/install/ProotXfceAssetInstaller.kt` (`installInto`, injectable extract) always leaves guest copies in `$PREFIX/tmp/flux_xfce_assets` (guest `/tmp/flux_xfce_assets` = `FLUX_ASSET_DIR`). Stock Android tar can't run `xz` (rc 127), so host `.tar.xz` extracts are skipped, and the guest's GNU tar extracts the copies. Never delete those copies on a host failure (v2.1.3 regression). PRoot guest scripts get `FLUX_PROOT=1` (fallback: non-zero `TracerPid`). `setup_customization_xfce.sh` uses it to skip the full `papirus-icon-theme` apt package, a many-minute unpack under PRoot.
- **Never follow symlinks in recursive file ops.** Guest homes link `~/storage/*` to shared storage. Use `KT/core/system/SafeFiles.kt` (`deleteTree`, `copyTree`, `walkNoFollow`, `isSymlink`; java.nio NOFOLLOW_LINKS). `SymlinkSafetyContractTest` fails on `deleteRecursively`, `copyRecursively`, `walkTopDown` and `File.walk()` in production code.
