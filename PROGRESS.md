- 2026-10-19: v2.1.0 makes the app Ubuntu PRoot-first (story US-1). Ubuntu-only onboarding; Home is an Ubuntu dashboard (Distros tab removed, DistroScreen deleted); cold launch auto-starts the XFCE desktop after a 1.5 s cancellable countdown, with a Settings switch and a crash-loop guard (UbuntuLaunchPreferences). Other installed distros stay on disk, untouched.
- 2026-10-19: Recursive file ops must never follow symlinks: use `core/system/SafeFiles` (NOFOLLOW). `SymlinkSafetyContractTest` guards against `deleteRecursively`/`copyRecursively`/`walkTopDown`. Guest homes hold `~/storage/*` links to shared storage, so a following walk could wipe the user's files.
- 2026-10-19: Guest `~/storage` links (shared, downloads, documents, dcim, pictures, music, movies) are created by `GuestStorageLinks` in `/home/flux` and `/root`; never deleted or replaced. ivarna uses All files access; API ≤29 uses legacy READ/WRITE_EXTERNAL_STORAGE; zenithblue gains no MANAGE_EXTERNAL_STORAGE.
- 2026-10-19: `UbuntuDocumentsProvider` (`${applicationId}.documents`) exposes "Ubuntu" (home) and "Ubuntu filesystem" (/) SAF roots; guest-style link resolution confined to the rootfs + shared storage. Docs reached through a symlinked directory are browse/create only (no delete/move/rename, no tree grant), so client-side recursive moves can't empty shared storage.
- 2026-10-19: Release APK shrunk 177→65 MB: `bootstrap.tar` deflated in the APK, native libs stripped (NDK 29), English-only resources. Releases are signed with the fork's own key in `~/.config/fluxlinux-ubuntufied/signing/` (repo-root `keystore.properties` copy, gitignored); never regenerate it.
- 2026-10-20: v2.1.1: termux-x11 loads `libXlorie.so` from the read-only `dirname(base.apk)/lib/arm64` (nativeLibraryDir, via `TERMUX_X11_LIB_PATH`) over the script-extracted `/data/data/<pkg>/lib` copy, because Android 17 refuses `System.load` of a writable file. Keep `useLegacyPackaging = true` (extractNativeLibs): without it that read-only copy doesn't exist.
- 2026-10-20: v2.1.2: terminal opens Ubuntu directly (TerminalToolSelector removed; extras via long-press "+") over a distro picker, because only Ubuntu is installable in this fork. Ubuntu zsh plugin list is built at start-up from what's installed (ZshPluginSet.kt is the source of truth, script copy test-enforced), so partial network installs never print errors.
- 2026-10-20: v2.1.3: audit remediation (AUDIT_REPORT.md §6; 57 fixed, M14/L8 partial, L29 blocked on a toolchain decision). Chroot root helpers live in root-only /data/adb/fluxlinux/<pkg> and are SHA-256-checked before exec, never /data/local/tmp. PulseAudio uses a private unix socket, not 127.0.0.1:4713. Chroot mounts are guarded by a shared mkdir lock that is identical across 7 scripts (test-enforced).
- 2026-10-20: v2.1.4: stock Android tar can't run xz, so XFCE `.tar.xz` assets are unpacked by the guest. ProotXfceAssetInstaller must never delete the guest copies in `$PREFIX/tmp/flux_xfce_assets`: doing so in v2.1.3 sent fresh installs into a many-minute `papirus-icon-theme` apt unpack. PRoot guests get `FLUX_PROOT=1` and skip that package. Releases also ship a debug APK (live-rule).
- 2026-10-20: verify a release candidate on the real phone with the debug APK before publishing, over publishing first, because v2.1.3 shipped an L19 regression (Papirus apt stall) that unit tests couldn't catch and only the device showed.
- 2026-10-20: v2.1.5: extra-keys rows 1–2 are Termux's default layout (`/` and `―` kept over the user's own Termux ☰/⇳, because FluxLinux has no session drawer). Key repeat is Termux-constant (400 ms, then 80 ms, checked against termux-app ExtraKeysView) by default, with the speed-up behind the "Accelerate held keys" switch, because the user prefers a constant speed.
- 2026-10-20: v2.1.6: the terminal's top bar and tab row are replaced by a Termux-style left session drawer, because the user wants the height. M3 `ModalNavigationDrawer` can't start its drag over the `AndroidView` TerminalView, so a 20dp `DrawerEdgeZone` strip owns the swipe, and a fixed ☰ key in the extra-keys bar is the fallback. Its `systemGestureExclusion` band is 192dp (Android caps it at 200dp per edge) and is untested on device: the user's phone uses 3-button nav. Extra keys are two 12-key rows sharing one horizontal scroll.
- 2026-10-20: v2.1.7: the host bootstrap had no `usr/bin/sh`, so every Termux wrapper with a `#!$PREFIX/bin/sh` shebang (`am`, `su`, `getprop`, …) failed in termux-exec's `linker64` path. `assemble_bootstrap.py` now adds `sh -> bash`, chosen over the tracked dash deb so fresh and repaired installs run the same interpreter. `HostShLink` adds it to existing installs, because `BootstrapInstaller` never re-extracts on upgrade. The scripts' early `am start` of the X11 activity was dropped, since once `sh` works it would open the display before `FLUX_DESKTOP_READY`. Verified on the SM-S938B: link created on the existing prefix, crash buffer clean on desktop start, `getprop` exits 0.
- 2026-10-21: v2.1.8: after `apt upgrade` installed rust-coreutils 0.10, proot `--link2symlink` turned its hard links into `/.l2s` links, and Ubuntu's argv[0]-vs-executable check (uutils #10135) refused every utility. The fix is host-side (`GuestCoreutilsRepair` repoints `/usr/{bin,sbin}` at `gnu*`), because every proot entry runs the guest's own `env` first, so no guest script can run on a broken install. `--link2symlink` stays, since Android blocks hard links. Setup switches to `coreutils-from-gnu` and must name `coreutils-from-uutils-`, because apt 3 won't drop that Protected package on its own. Verified on the SM-S938B: relink, then the manual switch.
- 2026-11-02: Ubuntu chroot is back as a first-class runtime next to PRoot (branch feat/ubuntu-chroot), because the user's phone is rooted now. `UbuntuRuntime` (core/utils) is the SSOT: the mode picks `ubuntu` or `ubuntu_chroot` for Home, auto-start (crash guard keyed per id), onboarding (runtime choice only when root is found), the terminal default tab and Files; both installs coexist and switching never touches either. Root probes never run on the main thread, and Home re-probes on resume only after a grant (a denied Magisk prompt otherwise loops).
- 2026-11-02: the Ubuntu guest user is `akane` (/home/akane) in both PRoot and chroot, at the user's request; legacy distros keep `flux`. Existing installs are renamed in place (PRoot: host-side `GuestUserMigration`; chroot: the helper's root-side block, an identical copy in setup_guest_chroot.sh) with a `home/flux -> akane` compat link, chosen over a fresh user so data, OMZ and absolute /home/flux paths survive. If a rename can't run, login and every setup script stay on `flux` rather than creating a second account. New users get their name as password.
- 2026-11-02: chroot Files go through root (`RootGuestFs`, BusyBox applets first, single-quoted paths, rootfs confinement checked before and inside each root script) because SELinux hides /data/local/tmp/chrootUbuntu from the app uid. Host mounts inside the chroot (/proc, /sys, /dev, /sdcard bind) are list-only, so a SAF delete can never reach shared storage or host /dev; ~/storage links resolve to shared storage directly, browse/create only.

## Known issues / to do
- `ProotXfceAssetInstaller.writeAtomically` uses a fixed `.tmp` name, so two installs running at once can collide.
- `MountLockTest` adds about 45 s to the unit suite because it waits on real timeouts. Make those timeouts injectable.
- `.agent/workflows/fdroid-update.md` is stale for this fork: wrong repo (`abhay-byte/fluxlinux`), `assembleRelease`, and no debug APK.

- Chroot setup's flux→akane rename (setup_guest_chroot.sh) doesn't take the helper's mount lock, so a desktop start during setup could race it.
- Chroot Files can't open `rw`/`rwt` (random access) through root; editors that open files that way fail on chroot files.
