# FluxLinux v2.1.0 Release Notes (Ubuntu edition)

### 1. Ubuntu-first
Ubuntu 26.04 PRoot is the focus. Onboarding installs Ubuntu directly (no distro or method pick) and includes a storage-access step. The main screen is an Ubuntu dashboard; the distro list and Distros tab are gone.

### 2. Direct start
After first-run setup, opening the app starts the Ubuntu XFCE desktop automatically.
- Short "Starting Ubuntu…" screen with Cancel
- Turn it off in Settings
- A crash-loop guard stops auto-start after repeated failed launches and shows recovery controls instead

### 3. Ubuntu in Android file managers
Ubuntu's home (`/home/flux`) and the whole filesystem (`/`) appear as "Ubuntu" and "Ubuntu filesystem" roots in the system Files app and any SAF picker, through a DocumentsProvider.
- Symlinks resolve inside the Ubuntu filesystem
- "Open in Files" button in the app

### 4. Termux-style `~/storage` links
Created in the Ubuntu home (and `/root`): `shared` → `/storage/emulated/0`, and `downloads`, `documents`, `dcim`, `pictures`, `music`, `movies` → `Download`, `Documents`, `DCIM`, `Pictures`, `Music`, `Movies` under it.
- ivarna (F-Droid/GitHub) build: "All files access" on Android 11+; READ/WRITE_EXTERNAL_STORAGE on Android 8-10
- Play build does not request All files access

### 5. Existing installs preserved
Upgrading keeps installed distros and guest home files. Other distros installed by older versions stay on disk, untouched. File operations never follow symlinks, so deleting or measuring a container cannot touch shared storage through `~/storage`.

### 6. Recovery controls
Terminal, root shell, stop session, repair, and storage/file access remain available.

### 7. Smaller release APK
About 65 MB instead of about 177 MB: compressed bootstrap, stripped native libraries, English-only resources.

### Upgrading
This release is signed with this fork's own key. It cannot update over F-Droid or Play builds of upstream FluxLinux. Both use `com.ivarna.fluxlinux`, so uninstall an existing upstream install first (this deletes its data). Updating from an earlier release of this fork keeps your data.

### Known limitations
- Auto-start needs the arm64 host.
- The on-device desktop runtime was verified only at the UI/provider level in this release's QA.
