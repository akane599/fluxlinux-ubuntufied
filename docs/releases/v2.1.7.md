# FluxLinux v2.1.7 Release Notes (Ubuntu edition)

### 1. Host `sh` fix
- The app's built-in Termux environment had no `sh`. About 30 Termux helper commands that start with an `sh` line (`am`, `su`, `getprop`, `logcat`, `pm`, `settings`, `termux-open` and others) failed with `linker: unable to open file …/usr/bin/sh`. That error showed up in the system crash log every time the desktop started.
- The bootstrap now includes `sh` (a link to `bash`). Existing installs get the link automatically the next time the app starts; nothing is replaced or deleted.
- Those helper commands now work in the host shell.

### 2. Desktop window opening
- The desktop start scripts no longer try to open the X11 window themselves. The app opens it once the desktop is ready, as before. (The scripts' early attempt only ever failed silently; with `sh` fixed it would have opened the window too early.)

### Migration Notes
- Upgrading from v2.1.x keeps your Ubuntu install and files.

### Checksums
- SHA-256 for both APKs is listed on the GitHub release page. The debug APK is for diagnosis only: it is signed with a debug key, so it can't update a release install.
